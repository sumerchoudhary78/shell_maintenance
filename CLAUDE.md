# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`caelestia-shell` — a desktop shell for Hyprland built on [Quickshell](https://quickshell.outfoxxed.me).
The UI is ~264 QML files; a C++ plugin (`plugin/`) provides native QML types (audio DSP, config schema,
image caching, models, custom-shader effects). The shell is configured at runtime from
`~/.config/caelestia/shell.json`; it is *not* a typical app you "run a dev server" for — you build the
C++ plugin, point Quickshell at the QML, and Quickshell hot-reloads QML edits.

This checkout is a fork named `shell_maintenance`. It has **no git tags**, which matters for builds (below).

## Dev environment (run for development)

No install needed: build the C++ plugin once, then run Quickshell directly on this checkout. QML edits
hot-reload live (`shell.qml` has `settings.watchFiles: true`); only C++ changes need a rebuild + restart.

```sh
# 1. Build the plugin. NOTE: this fork has NO git tags, so `git describe --tags` fails — you MUST pass
#    VERSION/GIT_REVISION or configure aborts (see CMakeLists.txt). CI passes empty values.
cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=RelWithDebInfo -DVERSION=0 -DGIT_REVISION="$(git rev-parse HEAD)"
cmake --build build        # plugin QML modules → build/qml, `version` binary → build/lib

# 2. Run this checkout directly (kill any running caelestia shell instance first)
export CAELESTIA_LIB_DIR="$PWD/build/lib" QML2_IMPORT_PATH="$PWD/build/qml:$QML2_IMPORT_PATH"
qs -p .

# C++ change loop: cmake --build build, then restart qs
```

Headless smoke test (CI-style; expect "No PanelWindow backend loaded" — anything else is a real error):

```sh
QT_QPA_PLATFORM=offscreen CAELESTIA_LIB_DIR="$PWD/build/lib" \
  QML2_IMPORT_PATH="$PWD/build/qml:$QML2_IMPORT_PATH" timeout 3 qs -p .
```

The repo's `.envrc` (direnv + nix devshell, builds with clazy) **does not work as-is on this fork**: it omits
`-DVERSION`, so configure aborts on the tagless checkout, and `direnv`/`clazy` are devshell-only. Use the
explicit commands above. `nix develop` still works as a devshell (cmake, ninja, clazy, qt6, fonts,
`CAELESTIA_XKB_RULES_PATH`).

## Release build

Two supported paths: Nix (reproducible, handles versioning/fonts/runtime-dep wrapping itself) and CMake
system install (Arch/manual).

```sh
# Nix — version/rev are injected by the flake, no VERSION flags needed
nix run                       # build + run directly
nix build                     # → result/bin/caelestia-shell (wrapped qs with fonts + runtime deps)
nix build .#with-cli          # incl. the caelestia CLI (needed for full IPC functionality)
nix build .#debug             # debug build (symbols kept)

# CMake system install — same VERSION/GIT_REVISION caveat as above
cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_INSTALL_PREFIX=/ \
  -DVERSION=0 -DGIT_REVISION="$(git rev-parse HEAD)"
cmake --build build
sudo cmake --install build    # → /usr/lib/caelestia, /usr/lib/qt6/qml, /etc/xdg/quickshell/caelestia
qs -c caelestia               # or: caelestia shell -d   (CLI variant)
```

`ENABLE_MODULES` (`extras;plugin;shell`, default all) selects what builds: `extras` = a `version` binary,
`plugin` = the C++ QML modules, `shell` = installs the QML tree (`assets components modules services utils`)
+ `shell.qml` to `INSTALL_QSCONFDIR` (`etc/xdg/quickshell/caelestia`).

**Editable install** (README "manual installation" tip — install the QML tree into your user config so the
installed copy is this checkout):

```sh
mkdir -p ~/.config/quickshell/caelestia
cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DINSTALL_QSCONFDIR=~/.config/quickshell/caelestia \
  -DVERSION=0 -DGIT_REVISION="$(git rev-parse HEAD)"
cmake --build build && sudo cmake --install build && sudo chown -R "$USER" ~/.config/quickshell/caelestia
qs -c caelestia
```

The CMake `shell` install **patches `settings.watchFiles` to `false`** for production — don't rely on
hot-reload in installed copies; for live-reload development run `qs -p .` on the checkout instead.

## Lint & format (CI gates — must pass before merge)

CI (`.github/workflows/check-format.yml`, `lint.yml`) runs these; the Qt tools live at `/usr/lib/qt6/bin/`:

```sh
# QML formatting (must produce no diff)
qmlformat <file> | diff -u <file> -          # check;  qmlformat -i <file> to fix

# QML structure conventions (custom linter, see "QML conventions" below)
python3 scripts/qml-lint-conventions.py      # check;  add --fix to rewrite in place

# QML static lint — needs built plugins in build/qml and a .qmlls.ini generated by quickshell:
QT_QPA_PLATFORM=offscreen QML2_IMPORT_PATH="$PWD/build/qml:$QML2_IMPORT_PATH" timeout 2 qs -p .
qmllint --import disable -I build/qml <import paths from .qmlls.ini> **.qml   # excludes modules/controlcenter/

# C++ formatting (LLVM base, 4-space, 120 col, left-aligned pointers — see .clang-format)
find plugin extras -name '*.cpp' -o -name '*.hpp' | xargs clang-format --dry-run --Werror   # clang-format -i to fix
```

`qmllint` runs with `--import disable` and therefore **needs the compiled `Caelestia.*` plugins in `build/qml`**
to resolve types — build the plugin before linting. `modules/controlcenter/` is excluded from QML lint.

## Architecture

### QML module/import model (read this first)

Three import flavors coexist; the custom linter enforces their ordering:

- **`import qs.<dir>`** — Quickshell auto-exposes the shell config root as the `qs` QML module, so
  `qs.components`, `qs.services`, `qs.utils`, `qs.modules.bar.popouts` map **directly to this repo's
  top-level directories**. There are no hand-written `qmldir` files; the namespace is generated. This is the
  primary way modules reach each other.
- **`import Caelestia` / `import Caelestia.Config` / `.Services` / `.Internal` / `.Models` / `.Images` /
  `.Components` / `.Blobs`** — native types from the C++ plugin (compiled to `INSTALL_QMLDIR`). Typos in these
  URIs fail silently at runtime.
- **Relative quoted imports** (`import "modules"`) — used by `shell.qml` and a few siblings.

Singletons (`pragma Singleton`, ~26 of them across `services/` and `utils/`) are accessed by type name after
import, e.g. `Colours.palette.m3primary`, `Hypr.focusedMonitor`, `Visibilities.getForActive()`.

### C++ plugin (`plugin/src/Caelestia/`)

Each subdirectory is one QML module URI, registered via `qt_add_qml_module` + `QML_ELEMENT`/`QML_SINGLETON`
(a `qml_module()` CMake helper wraps this and links a shared precompiled-header lib `caelestia-pch`). Notable:

- **`Config/`** — the entire config schema is C++ (see below).
- **`Services/`** — audio DSP on background `QThread`s: `CavaProvider` (libcava spectrum), `BeatTracker`
  (aubio BPM/beat), raw PipeWire capture. They share a `Service` base with `ref()`/`unref()` counting so the
  expensive pipelines only run while something binds them. Don't block in the processor loop.
- **`Internal/`** — painted items (`ArcGauge`, `VisualiserBars`, `SparklineItem`) and `HyprExtras` (raw
  Hyprland IPC over the `$XDG_RUNTIME_DIR/hypr/<sig>/` unix socket; fails silently if absent).
- **`Blobs/`** — morphing rounded-rect rendering via custom GLSL (`shaders/blob.{vert,frag}`, SDF
  `smin`/`smax`). The fragment shader's uniform layout (std140) must match the C++ struct exactly.
- **`Images/`**, **`Models/`**, **`Components/`** (`LazyListView`), plus root utilities: `Qalculator`
  (libqalculate), `AppDb` (.desktop apps + frequency), `ImageAnalyser` (dominant colour), `Requests`,
  `Toaster`, `CUtils`.

### Configuration system (`plugin/src/Caelestia/Config/`)

`shell.json` → C++ parse → QML, all native. `GlobalConfig` (from `shell.json`) and `TokenConfig` (from
`shell-tokens.json`) are `QML_SINGLETON`s extending `RootConfig` (file-watching via `QFileSystemWatcher`,
500 ms debounced auto-save, retry-on-parse-fail). Schema nodes extend `ConfigObject` and declare fields with
the **`CONFIG_PROPERTY`** (per-monitor-overridable) / **`CONFIG_GLOBAL_PROPERTY`** (global-only) /
**`CONFIG_SUBOBJECT`** macros — defaults live in the declarations, so adding an option = adding a macro line
in the relevant `*config.hpp`.

- **Per-monitor overrides**: `MonitorConfigManager` lazily builds overlay `GlobalConfig`/`TokenConfig` per
  screen from `~/.config/caelestia/monitors/<screen>/`. Overlays `syncFromGlobal()` then watch global for
  unset keys. `CONFIG_GLOBAL_PROPERTY` writes are ignored on overlays (the README lists which options are
  global-only).
- **Token scaling**: the `appearance.*.scale` values in `shell.json` are multipliers over base tokens in
  `shell-tokens.json`. `appearanceconfig.cpp` computes e.g. `rounding.small() == token.small() * scale`
  lazily, relaying token change signals. QML reads these via the **`Config` and `Tokens` attached
  properties** (screen-aware): set `Config.screen`/`Tokens.screen` at a window root and it propagates to
  children, resolving the right per-monitor overlay.

### UI modules (`modules/`) + drawers + IPC

`shell.qml` instantiates `Background`, `Drawers`, `AreaPicker`, `Lock`, `ConfigToasts`, `Shortcuts`,
`BatteryMonitor`, `IdleMonitors`.

- **Drawers**: `modules/drawers/ContentWindow.qml` is a single Wayland layer-shell window per screen holding
  all panels (bar, dashboard, launcher, session, sidebar, utilities, OSD, notifications) with `BlobGroup`
  deformation. Visibility is centralized: `components/DrawerVisibilities.qml` (a `PersistentProperties` with
  per-panel booleans) is registered per-monitor in the `Visibilities` service; shortcuts/IPC flip the
  booleans, `Interactions.qml` reacts. Fullscreen toggles panels off.
- **IPC** (backs `caelestia shell <target> <fn>`): `IpcHandler { target: "..." }` blocks are scattered across
  the files that own the state — `target drawers`/`controlCenter`/`toaster` in `modules/Shortcuts.qml`,
  `lock` in `modules/lock/Lock.qml`, `picker` in `modules/areapicker/AreaPicker.qml`, and `notifs`/`mpris`/
  `audio`/`hypr`/`wallpaper`/`brightness`/`gameMode` in the corresponding `services/*.qml`. Add a CLI command
  by adding a function to the relevant `IpcHandler`. `caelestia shell -s` lists them all.
- **Launcher** (`modules/launcher/`): plugin/action search. Each plugin (`services/Apps.qml`,
  `Actions.qml`, `Schemes.qml`, `M3Variants.qml`) is a `Searcher` singleton; `actionPrefix` (default `>`)
  switches to actions/scheme/wallpaper/variant, `specialPrefix` (default `@`) adds app-search modifiers.
- **Lock** (`modules/lock/`): `WlSessionLock` + PAM. `Pam.qml` loads two contexts (`passwd`, `fprint`) from
  `assets/pam.d/` (paths are hardcoded — must exist). Lock background is a preloaded screencopy blur.

### Services (`services/`)

QML singletons that wrap system state and shell out to tools, exposing reactive properties widgets bind to.
Patterns: `Process`+`StdioCollector` for command output, `FileView` for `/proc` and config files, debounce
`Timer`s to batch external commands, `ref`/`refCount` to start/stop polling only when consumed.
Highlights: **`Colours`** (Material 3 palette, `layer()` transparency, reloads Hypr layerrules on
transparency change), **`Hypr`** (workspaces/monitors/toplevels via `HyprExtras`), **`Audio`**, **`Players`**
(MPRIS), **`Notifs`**/`NotifData` (D-Bus notification server, persisted to `notifs.json`), **`SystemUsage`**
(CPU/GPU/mem/disk), **`Brightness`** (ddcutil/asdbctl/brightnessctl), **`Network`**/`Nmcli`, **`Wallpapers`**.

### Components & styling (`components/`)

**Always use the `Styled*` wrappers, never raw QtQuick primitives.** `StyledText`, `StyledRect`,
`StyledClippingRect` pull font/colour/rounding from `Tokens`/`Colours` and have built-in colour-animation
behavior. Other conventions:

- Pull every design value from `Tokens.*` (`Tokens.font.family.sans`, `Tokens.padding.normal`,
  `Tokens.rounding.small`, `Tokens.anim.durations.normal`) — don't hardcode.
- Animate with **`Anim`** (NumberAnimation with a `Type` enum → token duration+easing) and **`CAnim`**
  (fixed-duration ColorAnimation) instead of bare `NumberAnimation`/`ColorAnimation`; **`AnchorAnim`** for
  anchor transitions.
- `MaterialIcon` (extends `StyledText`) renders the Material Symbols font with variable axes (FILL/GRAD/opsz/wght).
- `StateLayer` gives Material ripple feedback on interactive components.
- GPU effects via `layer.effect` (`effects/Elevation`, `Colouriser`, `OpacityMask`); shaders in
  `assets/shaders/*.frag` compile to `.qsb` at build time — reference the `.qsb`, not the `.frag`.
- Reusable controls in `components/controls/` (`IconButton`, `StyledSwitch`, `StyledSlider`,
  `StyledTextField`, `CircularProgress`), containers in `components/containers/`.

### Utilities (`utils/`)

Singletons: `Paths` (XDG dirs, `CAELESTIA_LIB_DIR`), `Icons` (icon-name mappings), `Searcher` (fzf/fuzzy),
`Strings` (regex cache), `Images` (valid-image checks), `SysInfo` (`/etc/os-release`, uptime),
`NetworkConnection`.

## QML conventions (enforced by `scripts/qml-lint-conventions.py`)

Within each QML object, members must appear in this order, each group blank-line-separated:
`id` → property declarations → signals → JS functions → object property bindings → child objects →
component definitions. Imports: relative quoted imports first, then module imports grouped
`QtQuick → Qt → Quickshell → M3Shapes → Caelestia → qs.*` and depth-sorted (fewer dots first); pragmas
before imports with a blank line. `--fix` auto-rewrites. New files outside `modules/controlcenter/` are lint-checked.
